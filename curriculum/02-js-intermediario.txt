@@module js-funcoes-avancadas | js | Funções de verdade | Escopo, closures e recursão: como as funções realmente funcionam por dentro.

@@lesson js-escopo-closures | Escopo e closures | 25
@@body
**Escopo** é a região do código onde um nome existe.

- **Global:** visível em todo o programa. Evite.
- **De função:** nomes declarados dentro de uma função só existem nela.
- **De bloco:** `let` e `const` dentro de `{ }` (um `if`, um `for`) ficam presos ao bloco. `var` ignora blocos, mais um motivo para evitá-lo.

```js run
const global = "visível em todo lugar";

function teste() {
  const local = "só aqui dentro";
  console.log(global, local);
}
teste();
// console.log(local); // ReferenceError: local is not defined
```

Uma função enxerga o escopo onde foi **criada** e os escopos acima dele. Se um nome interno repete um externo, ele o **sombreia** (shadowing).

### Closure

Uma **closure** é uma função que continua com acesso às variáveis do escopo onde nasceu, mesmo depois que esse escopo terminou:

```js run
function criarContador() {
  let total = 0;           // variável "privada"
  return () => ++total;
}

const a = criarContador();
const b = criarContador();
console.log(a(), a(), a()); // 1 2 3
console.log(b());           // 1 (outro contador, outro total)
```

Ninguém de fora consegue mexer em `total`, só pela função devolvida. Closures dão **encapsulamento** (dados privados), são a base de fábricas de funções, `debounce`, `memoize` e dos hooks do React.

### Hoisting e a "zona morta"

Declarações `function` são içadas (podem ser chamadas antes de aparecerem). Variáveis `let`/`const` existem desde o início do bloco, mas usá-las antes da linha da declaração causa erro (a *temporal dead zone*).

```js
console.log(x); // ReferenceError: Cannot access 'x' before initialization
let x = 5;
```

      if (v > saldo) throw new Error("Saldo insuficiente");
      saldo -= v;
    },
    saldo() { return saldo; },
  };
}

@@lesson js-recursao | Recursão | 25
@@body
**Recursão** é quando uma função chama a si mesma para resolver uma versão menor do mesmo problema. Toda função recursiva precisa de:

1. **Caso base:** a situação mais simples, que responde sem chamar a si mesma.
2. **Passo recursivo:** reduz o problema e chama a função de novo.

```js run
function fatorial(n) {
  if (n <= 1) return 1;          // caso base
  return n * fatorial(n - 1);    // passo recursivo
}
console.log(fatorial(5)); // 5 * 4 * 3 * 2 * 1 = 120
```

Para `fatorial(3)` o programa empilha: `3 * fatorial(2)` → `2 * fatorial(1)` → `1`. Depois desempilha multiplicando. Cada chamada ocupa espaço na **pilha de chamadas**. Sem caso base (ou com um que nunca é alcançado), a pilha estoura: `RangeError: Maximum call stack size exceeded`.

### Quando usar

Recursão brilha em estruturas **aninhadas** (árvores, pastas dentro de pastas, JSON profundo), onde um laço simples não basta:

```js run
function somarAninhado(lista) {
  let total = 0;
  for (const item of lista) {
    total += Array.isArray(item) ? somarAninhado(item) : item;
  }
  return total;
}
console.log(somarAninhado([1, [2, [3, 4]], 5]));
```

Para problemas simples e repetitivos, um laço é mais eficiente. Para problemas "de dentro para dentro", a recursão costuma ser mais clara.

function fatorial(n) {
  if (n <= 1) return 1;
  return n * fatorial(n - 1);
}

function potencia(base, expoente) {
  if (expoente === 0) return 1;
  return base * potencia(base, expoente - 1);
}

function contagemRegressiva(n) {
  if (n <= 0) return [];
  return [n, ...contagemRegressiva(n - 1)];
}

function profundidade(lista) {
  let maior = 0;
  for (const item of lista) {
    if (Array.isArray(item)) maior = Math.max(maior, profundidade(item));
  }
  return 1 + maior;
}

@@body
Programadores experientes não "sabem a resposta": eles têm um **método**. Use estes passos sempre:

1. **Entenda.** Reescreva o problema com suas palavras. Quais são as entradas? Qual é a saída?
2. **Exemplos.** Escreva 2 ou 3 casos à mão, com a resposta esperada.
3. **Casos de borda.** Lista vazia? Valores repetidos? Número negativo? Texto vazio?
4. **Plano em português.** Descreva os passos sem código (pseudocódigo).
5. **Implemente o menor pedaço** que funciona e teste logo.
6. **Refine.** Só depois pense em deixar mais elegante ou mais rápido.

### Exemplo: "o maior número de uma lista"

- Entrada: lista de números. Saída: o maior, ou `undefined` se vazia.
- Exemplos: `[3, 9, 2]` → `9`; `[-5, -1]` → `-1`; `[]` → `undefined`.
- Plano: guardar o "maior até agora" (o primeiro item); percorrer o resto; se achar um maior, trocar.

```js run
function maior(lista) {
  if (lista.length === 0) return undefined;
  let melhor = lista[0];
  for (const n of lista) {
    if (n > melhor) melhor = n;
  }
  return melhor;
}
console.log(maior([3, 9, 2]), maior([-5, -1]), maior([]));
```

Observe que inicializar `melhor` com `0` quebraria o caso `[-5, -1]`. Pensar nos casos de borda **antes** evita esse tipo de bug.

> **Se travar:** explique o problema em voz alta (método do "patinho de borracha"), desenhe, simplifique o problema ou resolva primeiro um caso menor.

@@solution
function segundoMaior(lista) {
  const distintos = [...new Set(lista)].sort((a, b) => b - a);
  return distintos[1];
}

function mediana(lista) {
  if (lista.length === 0) return undefined;
  const ord = [...lista].sort((a, b) => a - b);
  const meio = Math.floor(ord.length / 2);
  return ord.length % 2 === 1 ? ord[meio] : (ord[meio - 1] + ord[meio]) / 2;
}

@@lesson js-erros-debug | Erros e depuração | 25
@@body
Erros fazem parte do trabalho. Quem programa bem sabe **ler** o erro e **tratá-lo**.

### Lendo uma mensagem de erro

`TypeError: Cannot read properties of undefined (reading 'nome')` diz três coisas: o **tipo** (`TypeError`), o **que** aconteceu (tentou ler `nome` de algo `undefined`) e, no console do navegador, **onde** (linha do arquivo). Comece sempre pela primeira linha.

Erros comuns: `ReferenceError` (nome inexistente), `TypeError` (uso errado de um valor), `SyntaxError` (código mal escrito), `RangeError` (valor fora do limite, como pilha estourada).

### `try`, `catch`, `finally` e `throw`

```js run
function dividir(a, b) {
  if (b === 0) throw new RangeError("Divisão por zero");
  return a / b;
}

try {
  console.log(dividir(10, 2));
  console.log(dividir(1, 0));
  console.log("não chega aqui");
} catch (erro) {
  console.log("Falhou:", erro.message);
} finally {
  console.log("sempre executa");
}
```

Lance erros com `throw new Error("mensagem clara")`. Trate (`catch`) só quando souber **o que fazer** com o erro; senão, deixe subir.

### Estratégias de depuração

- **`console.log` com rótulo:** `console.log("total:", total)` mostra o valor no ponto exato.
- **Isolar:** teste a função sozinha com entradas simples.
- **Pontos de interrupção:** nas ferramentas do navegador (F12 → Sources) você pausa a execução e inspeciona variáveis passo a passo. A instrução `debugger;` faz o mesmo.
- **Reproduza o bug** de forma mínima antes de tentar consertar.

@@module js-organizacao | js | Código organizado | Classes, estruturas de dados e módulos: como projetos reais se organizam.

@@lesson js-classes | Classes e orientação a objetos | 30
@@body
Uma **classe** é um molde para criar objetos com os mesmos dados e comportamentos.

```js run
class Retangulo {
  constructor(largura, altura) {
    this.largura = largura;
    this.altura = altura;
  }

  area() {
    return this.largura * this.altura;
  }

  get perimetro() {
    return 2 * (this.largura + this.altura);
  }

  static quadrado(lado) {
    return new Retangulo(lado, lado);
  }
}

const r = new Retangulo(3, 4);
console.log(r.area(), r.perimetro, Retangulo.quadrado(5).area());
```

- `constructor` roda em `new` e prepara o objeto.
- **Métodos** ficam na classe e são compartilhados por todas as instâncias.
- `get` cria uma propriedade calculada.
- `static` pertence à classe, não às instâncias.

### Campos privados

Campos com `#` só existem dentro da classe. É encapsulamento de verdade:

```js run
class Conta {
  #saldo = 0;
  depositar(v) { this.#saldo += v; }
  get saldo() { return this.#saldo; }
}
const c = new Conta();
c.depositar(20);
console.log(c.saldo);
// console.log(c.#saldo); // SyntaxError
```

### Herança

`extends` cria uma classe que reaproveita outra; `super` chama a original.

```js run
class Animal {
  constructor(nome) { this.nome = nome; }
  falar() { return `${this.nome} faz um som`; }
}
class Gato extends Animal {
  falar() { return `${super.falar()}: miau`; }
}
console.log(new Gato("Mia").falar());
```

> **Na prática:** herança cria acoplamento forte. Muitos times preferem **composição** (objetos que usam outros objetos) e usam herança com moderação.

@@lesson js-map-set-json | Map, Set e JSON | 25
@@body
Além de arrays e objetos, JS tem duas coleções muito úteis e um formato universal de dados.

### `Set`: itens únicos

```js run
const tags = new Set(["js", "ts", "js"]);
tags.add("node");
console.log(tags.size, tags.has("ts"));
console.log([...tags]);
```

O jeito mais curto de remover repetidos de um array: `[...new Set(lista)]`. Verificar `has` num `Set` é muito mais rápido que `includes` em array grande.

### `Map`: chave → valor, com qualquer tipo de chave

Diferente de objetos, mantém a ordem de inserção, aceita chaves de qualquer tipo e tem `size`.

```js run
const contagem = new Map();
for (const letra of "banana") {
  contagem.set(letra, (contagem.get(letra) ?? 0) + 1);
}
console.log(contagem);
console.log([...contagem.entries()]);
```

### JSON

**JSON** é um formato de texto para trocar dados entre sistemas.

```js run
const texto = JSON.stringify({ nome: "Ana", tags: ["a", "b"], extra: undefined });
console.log(texto);
console.log(JSON.parse(texto));
```

`JSON.stringify` descarta `undefined` e funções, e transforma `Date` em texto. `JSON.parse` lança erro se o texto for inválido (por isso você aprendeu `try/catch`).

### Copiando em profundidade

Para uma cópia **profunda** (que não compartilha objetos aninhados), use `structuredClone(obj)`.

```js run
const original = { lista: [1, 2] };
const copia = structuredClone(original);
copia.lista.push(3);
console.log(original.lista, copia.lista);
```

function frequencia(lista) {

function agruparPorTamanho(palavras) {

    mapa.get(p.length).push(p);

  return mapa;

@@lesson js-promises | Promises | 30
@@body
Algumas tarefas demoram: buscar dados na rede, ler arquivos, esperar um tempo. JS não trava esperando: ele continua rodando e avisa quando terminar. Uma **Promise** representa um resultado que **ainda vai chegar**.

Estados: **pending** (pendente) → **fulfilled** (deu certo, com um valor) ou **rejected** (deu errado, com um erro).

```js run
const espera = new Promise((resolve, reject) => {
  setTimeout(() => resolve("pronto!"), 200);
});

espera
  .then(valor => console.log(valor))
  .catch(erro => console.log("erro", erro))
  .finally(() => console.log("fim"));

console.log("isto aparece primeiro");
```

`then` recebe o valor e **devolve outra promise**, o que permite encadear. `catch` captura qualquer rejeição acima dele.

### Combinando promises

| Função | Resolve quando... |
| --- | --- |
| `Promise.all([...])` | **todas** deram certo (rejeita se uma falhar) |
| `Promise.allSettled([...])` | todas terminaram, com sucesso ou não |
| `Promise.race([...])` | a **primeira** terminar |
| `Promise.any([...])` | a primeira que der **certo** |

```js run
const rapida = new Promise(r => setTimeout(() => r("rápida"), 50));
const lenta = new Promise(r => setTimeout(() => r("lenta"), 150));
Promise.all([rapida, lenta]).then(r => console.log(r));
Promise.race([rapida, lenta]).then(r => console.log(r));
```

@@lesson js-async-await | async e await | 30
@@body
`async`/`await` é uma sintaxe que faz código assíncrono parecer sequencial. É construída em cima de Promises.

```js run
const esperar = (ms) => new Promise(r => setTimeout(r, ms));

async function tarefa() {
  console.log("começando");
  await esperar(300);        // pausa SÓ esta função
  console.log("300 ms depois");
  return "fim";
}

tarefa().then(console.log);
console.log("o resto do programa continua");
```

- Uma função `async` **sempre devolve uma Promise**.
- `await` só vale dentro de funções `async` (e no topo de módulos) e "desembrulha" o valor da promise.
- Erros viram exceções comuns: use `try/catch`.

```js run
async function buscar(id) {
  if (id < 0) throw new Error("id inválido");
  return { id };
}

async function main() {
  try {
    console.log(await buscar(1));
    console.log(await buscar(-1));
  } catch (e) {
    console.log("capturado:", e.message);
  }
}
main();
```

### Sequencial vs. paralelo

Cada `await` em sequência **espera o anterior**. Se as tarefas são independentes, dispare todas e espere juntas:

```js
// lento: 3 × 100 ms = 300 ms
for (const id of ids) resultados.push(await buscar(id));

// rápido: ~100 ms no total
const resultados = await Promise.all(ids.map(id => buscar(id)));
```

Esse erro (esperar em sequência o que poderia ser paralelo) é um dos problemas de desempenho mais comuns em código real.

@@lesson js-event-loop | O event loop | 25
@@body
JavaScript executa **uma coisa de cada vez** (uma única thread). Então como ele faz timers, rede e eventos sem travar? Com o **event loop**.

Peças do modelo:

1. **Pilha de chamadas:** o código que está rodando agora.
2. **Fila de microtarefas:** callbacks de `Promise` (`then`, `await`) e `queueMicrotask`.
3. **Fila de tarefas (macrotarefas):** `setTimeout`, eventos de clique, etc.

A regra do ciclo:

1. Executa todo o código síncrono até esvaziar a pilha.
2. Executa **todas** as microtarefas pendentes.
3. Pega **uma** macrotarefa, executa, e volta ao passo 2.

```js run
console.log("1 síncrono");

setTimeout(() => console.log("4 macrotarefa (timeout)"), 0);

Promise.resolve().then(() => console.log("3 microtarefa (promise)"));

console.log("2 síncrono");
```

Mesmo com `0` ms, o `setTimeout` roda **depois** das promises, porque microtarefas têm prioridade sobre macrotarefas.

### Consequência prática

Um laço pesado e síncrono **bloqueia tudo**: a página congela porque o navegador não consegue processar cliques nem desenhar. Divida trabalho pesado, use `await` entre etapas ou Web Workers.

Depois de um `await`, o resto da função vira uma microtarefa, executada quando o código síncrono atual terminar.

@@module js-profissional | js | Nível profissional | Imutabilidade, desempenho e padrões usados em código de produção.

@@lesson js-puras-imutabilidade | Funções puras e imutabilidade | 25
@@body
Uma **função pura** tem duas características:

1. Dadas as mesmas entradas, sempre devolve a mesma saída.
2. Não tem **efeitos colaterais**: não altera variáveis externas, nem os argumentos recebidos, nem imprime, nem acessa rede ou relógio.

```js run
// impura: altera o argumento
function adicionarImpura(lista, item) {
  lista.push(item);
  return lista;
}

// pura: devolve uma lista nova
function adicionarPura(lista, item) {
  return [...lista, item];
}

const original = [1, 2];
adicionarPura(original, 3);
console.log(original); // continua [1, 2]
```

Funções puras são fáceis de testar, de entender e de depurar, e são a base de bibliotecas como React e Redux.

Em vez de mudar dados, crie **cópias atualizadas**. Para dados aninhados, copie cada nível que muda:

@@lesson js-big-o | Desempenho e complexidade (Big O) | 30
@@body
Duas soluções corretas podem ter desempenhos radicalmente diferentes. A notação **Big O** descreve como o tempo cresce quando a **entrada** cresce.

| Notação | Nome | Exemplo | 1.000.000 itens |
| --- | --- | --- | --- |
| O(1) | constante | acessar `lista[i]`, `set.has(x)` | 1 passo |
| O(log n) | logarítmica | busca binária | ~20 passos |
| O(n) | linear | percorrer a lista uma vez | 1 milhão |
| O(n log n) | quase linear | `sort` | ~20 milhões |
| O(n²) | quadrática | laço dentro de laço | 1 **trilhão** |

Repare no último: um laço dentro de outro sobre uma lista grande pode levar minutos. Escondido também vale: `includes`, `indexOf` e `find` dentro de um laço **são** um segundo laço.

```js run
// O(n²): includes percorre a lista de novo a cada volta
function duplicadoLento(lista) {
  for (let i = 0; i < lista.length; i++) {
    if (lista.indexOf(lista[i]) !== i) return true;
  }
  return false;
}

// O(n): Set.has é praticamente instantâneo
function duplicadoRapido(lista) {
  const vistos = new Set();
  for (const x of lista) {
    if (vistos.has(x)) return true;
    vistos.add(x);
  }
  return false;
}

const grande = Array.from({ length: 20000 }, (_, i) => i);
console.time("lento");  duplicadoLento(grande);  console.timeEnd("lento");
console.time("rapido"); duplicadoRapido(grande); console.timeEnd("rapido");
```

@@hints
- temDuplicado: percorra guardando o que já viu em um Set; se já tem, devolva true.
- intersecao: crie new Set(b) e filtre a, depois remova repetidos de novo com Set.
- buscaBinaria: mantenha inicio e fim; calcule meio = Math.floor((inicio + fim) / 2); se ordenada[meio] é menor que o alvo, inicio = meio + 1; se maior, fim = meio - 1.
@@solution
function temDuplicado(lista) {
  const vistos = new Set();
  for (const x of lista) {
    if (vistos.has(x)) return true;
    vistos.add(x);
  }
  return false;
}

function intersecao(a, b) {
  const emB = new Set(b);
  return [...new Set(a.filter(x => emB.has(x)))];
}

function buscaBinaria(ordenada, alvo) {
  let inicio = 0;
  let fim = ordenada.length - 1;
  while (inicio <= fim) {
    const meio = Math.floor((inicio + fim) / 2);
    if (ordenada[meio] === alvo) return meio;
    if (ordenada[meio] < alvo) inicio = meio + 1;
    else fim = meio - 1;
  }
  return -1;
}

@@lesson js-padroes-funcionais | once, memoize, pipe e debounce | 35
@@body
Quatro utilitários clássicos que usam closures e funções de ordem superior. Você os encontra em bibliotecas como Lodash e em qualquer código profissional.

### `once`: executar só uma vez

```js run
function once(fn) {
  let jaFoi = false;
  let resultado;
  return (...args) => {
    if (!jaFoi) {
      jaFoi = true;
      resultado = fn(...args);
    }
    return resultado;
  };
}
const iniciar = once(() => { console.log("inicializando..."); return 42; });
console.log(iniciar(), iniciar());
```

### `memoize`: lembrar resultados

Guarda os resultados em um `Map` e evita recalcular quando os argumentos se repetem.

### `pipe`: compor funções

`pipe(f, g, h)(x)` equivale a `h(g(f(x)))`. É a forma de montar transformações como uma esteira:

```js run
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x);
const limpar = pipe(s => s.trim(), s => s.toLowerCase(), s => s.replaceAll(" ", "-"));
console.log(limpar("  Olá Mundo Novo "));
```

### `debounce`: esperar o usuário parar

Executa a função só depois de `ms` sem novas chamadas. Muito usado em campos de busca: em vez de buscar a cada tecla, busca quando a pessoa para de digitar.

```js
function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
}
```

Esse último você já poderia escrever sozinho: guarde o `timer` na closure, cancele o anterior com `clearTimeout` e agende um novo.

@@solution
function once(fn) {
  let jaFoi = false;
  let resultado;
  return (...args) => {
    if (!jaFoi) {
      jaFoi = true;
      resultado = fn(...args);
    }
    return resultado;
  };
}

function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const chave = JSON.stringify(args);
    if (!cache.has(chave)) cache.set(chave, fn(...args));
    return cache.get(chave);
  };
}

function pipe(...fns) {
  return (x) => fns.reduce((acc, fn) => fn(acc), x);
}

function debounce(fn, ms) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), ms);
  };
}

@@lesson js-novidades-es2026 | O que há de novo: ES2026 | 15
@@body
Todo ano o comitê **TC39** aprova uma nova edição do ECMAScript, a especificação por trás do JavaScript. A edição **ES2026** foi aprovada pela Ecma International em **30 de junho de 2026**. Segundo o levantamento publicado na época, ela não traz sintaxe nova: são **sete adições à biblioteca padrão**.

| Recurso | Para que serve |
| --- | --- |
| `Array.fromAsync()` | Criar array a partir de iteráveis assíncronos ou de promises |
| `Error.isError()` | Checar se um valor é um erro, mesmo vindo de outro contexto (iframe, worker) |
| `Math.sumPrecise()` | Somar números de ponto flutuante sem acumular erro de arredondamento |
| `Uint8Array` base64 e hex | Converter bytes de/para texto base64 e hexadecimal, sem bibliotecas |
| `Iterator.concat()` | Concatenar iteradores de forma preguiçosa |
| `JSON.parse` com acesso ao texto-fonte | Ler o texto original de cada valor (por exemplo, números grandes) no `reviver` |
| `Map.getOrInsert()` e similares ("upsert") | Obter um valor ou inserir um padrão em uma única chamada |

```js
// Antes: o padrão que aparecia em todo código
if (!mapa.has(chave)) mapa.set(chave, []);
mapa.get(chave).push(item);

// Com o upsert do ES2026
mapa.getOrInsert(chave, []).push(item);
```

O **Temporal**, a nova API de datas e horas que substitui o complicado `Date`, **não** entrou no ES2026. Pela lista de propostas finalizadas do TC39, ele está previsto para a edição de 2027.

### Como usar novidades com segurança

1. Confira o suporte no **MDN** (tabela de compatibilidade) e no `caniuse.com`.
2. No Node.js, veja a versão que você usa; no navegador, as versões que seus usuários têm.
3. Use detecção de recurso (`if (Array.fromAsync) { ... }`) ou um polyfill quando precisar suportar ambientes mais antigos.

> Esta lição é de leitura. Por causa da compatibilidade variável entre navegadores, os exercícios deste site usam só recursos amplamente disponíveis.
